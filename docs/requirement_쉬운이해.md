# 🟩 Mini Git 과제 - 아주 쉽게 이해하기  

> **이 문서는 뭘까?**  
> 이 문서는 "Mini Git"이라는 작은 프로그램을 만들기 위한 요구사항을 **초등학생도 이해할 수 있을 만큼 아주 쉽게** 풀어서 쓴 문서입니다.  
> 어려운 기술 용어는 최대한 피하고, 일상 생활에 비유해서 설명합니다.  

<br><br>

## 🟢 1. 이 과제가 뭐하는 건가요?  

### 🟡 비유로 이해하기: "마법의 노트"  
여러분이 그림을 그리는데, **실수해서 지우고 싶을 때** 또는 **어제 그린 그림이 더 마음에 들 때** 어떻게 하시나요?  
보통은 종이를 새로 꺼내서 다시 그리죠?  

**Git(깃)**은 **"마법의 노트"** 같은 거예요.  
- 내가 그린 모든 그림(코드)의 **역사**를 다 기억해줘요  
- 언제든 **과거로 돌아갈 수** 있어요  
- 친구랑 같이 그림을 그릴 때 **서로 방해되지 않게** 해줘요  

이번 과제는 이 **"마법의 노트"의 핵심 기능을 직접 만들어보는 것**입니다.  

<br><br>

## 🟢 2. 우리가 만들 프로그램: "Mini Git"  

### 🟡 어떤 프로그램인가요?  
- **이름**: Mini Git (미니 깃)  
- **종류**: 터미널(명령창)에서 쓰는 프로그램 (CLI = Command Line Interface)  
- **언어**: Python (파이썬)  

### 🟡 어떻게 생겼나요?  
```
mini-git> init "홍길동"
Initialized repository.
Current branch: main
Current user: 홍길동

mini-git> commit "첫 번째 그림"
[main a1b2c3] 첫 번째 그림

mini-git> log
commit a1b2c3 (홍길동, 2024-01-15 09:00:00) [main]
첫 번째 그림
```

**이런 식으로 명령어를 치면 결과를 보여주는 프로그램**입니다.  

<br><br>

## 🟢 3. 핵심 개념 3가지 (이것만 알면 반은 이해한 거예요!)  

### 🟡 ① 커밋 (Commit) = "저장 시점" / "스냅샷"  
> **쉽게**: 사진 찍기 📸  

- 내가 지금 작업한 내용을 **"찰칵!" 하고 사진 찍어서 저장**하는 거예요  
- 각 커밋마다 **고유한 번호(해시)**가 붙어있어요 (예: `a1b2c3`)  
- 커밋에는 이런 정보가 들어있어요:  
  - **해시(번호)**: 이 커밋만의 고유 ID  
  - **메시지**: 무슨 작업했는지 설명 (예: "로그인 기능 추가")  
  - **작성자**: 누가 했는지  
  - **시간**: 언제 했는지  
  - **부모**: 바로 전에 찍은 사진이 뭔지  

### 🟡 ② 브랜치 (Branch) = "가지" / "평행 우주"  
> **쉽게**: 복사본 만들기 📋  

- `main`이라는 **메인 줄기**가 있어요  
- 여기서 **가지(branch)를 치면** 독립된 작업 공간이 생겨요  
- 가지에서 작업해도 **메인 줄기에는 영향이 없어요**  
- 다 끝나면 다시 **합칠(merge) 수도 있어요**  

```
main:     ●───●───●───●
              │
feature:      ●───●───●
```

### 🟡 ③ 헤드 (HEAD) = "지금 내가 있는 곳" / "책갈피"  
> **쉽게**: 책갈피 📖  

- **지금 내가 어느 브랜치, 어느 커밋에 있는지** 알려주는 표시예요  
- `switch` 명령으로 책갈피를 옮길 수 있어요

## 🟢 4. 우리가 구현해야 할 명령어들 (기능 목록)  

### 🟡 저장소 만들기 & 설정  
| 명령어 | 뜻 | 쉽게 설명 |
|--------|-----|-----------|
| `INIT <이름>` | 초기화 | "새 노트 시작! 내 이름은 000" |
| `BRANCH <이름>` | 브랜치 생성 | "지금 페이지에서 새 가지 만들기" |
| `SWITCH <이름>` | 브랜치 이동 | "이 가지로 갈아타기" |

### 🟡 작업 저장하기 & 역사 보기  
| 명령어 | 뜻 | 쉽게 설명 |
|--------|-----|-----------|
| `COMMIT <메시지>` | 커밋 생성 | "지금 상태 사진 찍기 (설명 붙여서)" |
| `LOG` | 역사 보기 | "지금까지 찍은 사진들 순서대로 보기" |
| `LOG --sort-by=date` | 시간순 정렬 | "찍은 시간 순으로 정렬해서 보기" |
| `LOG --sort-by=author` | 작성자순 정렬 | "누가 찍었는지 순으로 정렬해서 보기" |

### 🟡 탐색 & 검색 (찾기 기능)  
| 명령어 | 뜻 | 쉽게 설명 |
|--------|-----|-----------|
| `PATH <커밋1> <커밋2>` | 최단 경로 | "두 사진 사이 가장 가까운 길 찾기" |
| `ANCESTORS <커밋>` | 조상 찾기 | "이 사진의 할아버지, 증조할아버지... 다 찾기" |
| `SEARCH <키워드>` | 키워드 검색 | "메시지에 이 단어 들어간 사진 찾기" |
| `SEARCH --author=<이름>` | 작성자 검색 | "이 사람이 찍은 사진 다 찾기" |

## 🟢 5. 어려운 용어 쉽게 풀기  

| 어려운 말 | 쉬운 말 | 비유 |
|-----------|---------|------|
| **Repository (저장소)** | 노트 / 창고 | 모든 사진이 들어있는 상자 |
| **Hash (해시)** | 고유 번호 / 지문 | 사람마다 다른 지문처럼, 커밋마다 다른 번호 |
| **DAG (방향성 비순환 그래프)** | 화살표가 한 방향으로만 가는 그림 | 가족 계보도처럼, 과거→미래로만 화살표가 감 |
| **Topological Sort (위상 정렬)** | 부모가 자식보다 먼저 나오게 줄 세우기 | 할아버지 → 아버지 → 나 순서로 줄 세우기 |
| **Inverted Index (역색인)** | 찾아보기 / 색인 | 책 뒤에 있는 "단어 → 페이지" 목록 |
| **BFS (너비 우선 탐색)** | 가까운 곳부터 동그랗게 퍼지며 찾기 | 물웅덩이에 돌 던지면 파문이 퍼지듯 |
| **Shortest Path (최단 경로)** | 가장 가까운 길 | 네이버 지도 "최단 거리" 길찾기 |

<br><br>

## 🟢 6. 데이터 구조: 어떻게 저장할까?  

### 🟡 커밋 하나 = 파이썬 딕셔너리 (사전)  
```python
commit = {
    "hash": "a1b2c3",           # 고유 번호
    "message": "로그인 추가",     # 설명
    "author": "홍길동",          # 작성자
    "timestamp": "2024-01-15 09:00:00",  # 시간
    "parents": ["parent_hash"]  # 부모 커밋 번호들 (리스트)
}
```

### 🟡 전체 저장소 = 해시맵 (딕셔너리)  
```python
# key: 커밋 해시, value: 커밋 객체
repository = {
    "a1b2c3": {...},
    "d4e5f6": {...},
    ...
}
```
> **왜 해시맵?** → 번호로 **바로 찾을 수 있어서** 빠르기 때문! (O(1))  

### 🟡 역색인 (Inverted Index) = 검색용 사전  
```python
# 키워드 → 그 단어가 들어간 커밋들
keyword_index = {
    "로그인": ["a1b2c3", "d4e5f6"],
    "기능": ["a1b2c3", "g7h8i9"],
    ...
}

# 작성자 → 그 사람이 만든 커밋들
author_index = {
    "홍길동": ["a1b2c3", "d4e5f6"],
    "김철수": ["g7h8i9"],
    ...
}
```
> **이게 왜 필요?** → 전체 커밋을 다 뒤지지 않고 **바로 찾아서** 빠르기 때문!

## 🟢 7. 알고리즘: 어떤 로직이 필요할까?  

### 🟡 1. 위상 정렬 (Topological Sort) - `LOG` 명령용  
> **목적**: 부모 커밋이 자식 커밋보다 **항상 먼저 나오게** 출력  

```
잘못된 순서:    자식 → 부모  ❌
올바른 순서:    부모 → 자식  ✅
```

**어떻게 하나요?**  
1. **진입 차수(들어오는 화살표 수)** 계산  
2. 진입 차수가 **0인 것부터 큐에 넣기**  
3. 하나 꺼내서 출력하고, **연결된 자식들의 진입 차수 줄이기**  
4. 진입 차수가 0이 되면 큐에 넣기  
5. 큐가 빌 때까지 반복  

### 🟡 2. BFS (너비 우선 탐색) - `PATH`, `ANCESTORS` 명령용  
> **목적**: 최단 경로 찾기 / 모든 조상 찾기  

**최단 경로 (PATH)**:  
- 두 커밋을 **무방향 그래프**로 보고 BFS로 찾기  
- 여러 경로면 **해시 문자열이 사전순으로 가장 작은 것** 선택  

**모든 조상 (ANCESTORS)**:  
- 시작 커밋에서 **부모, 부모의 부모... 계속 타고 올라가기**  
- 방문한 곳 또 안 가도록 **visited 집합**으로 체크  

### 🟡 3. 정렬 알고리즘 직접 구현 - `LOG --sort-by` 명령용  
> **규칙**: 파이썬 기본 `sorted()`, `list.sort()` **사용 금지!**  

**구현해야 할 것**:  
- **날짜 기준 정렬**: timestamp 비교  
- **작성자 기준 정렬**: author 이름 비교 (알파벳/가나다순)  

**추천 알고리즘** (둘 중 하나 이상 구현):  
- **병합 정렬 (Merge Sort)**: O(n log n), 안정 정렬  
- **퀵 정렬 (Quick Sort)**: 평균 O(n log n). 일반 제자리 구현은 불안정하지만 이 프로젝트의 세 그룹 구현은 안정 정렬  
- **삽입 정렬 (Insertion Sort)**: O(n²), 데이터 적을 때 괜찮음

## 🟢 8. 제약 사항 (꼭 지켜야 할 규칙)  

### 🟡 ❌ 쓰지 말 것  
- `sorted()` 함수  
- `list.sort()` 메서드  
- 그래프 전용 라이브러리 (networkx 등)  

### 🟡 ✅ 써도 되는 것  
- 기본 자료형: `list`, `dict`, `set`, `tuple`  
- 문자열 다루기: `split()`, `lower()`, `strip()` 등  
- 시간 다루기: `datetime`, `time` 모듈  
- 큐: `collections.deque`  
- 파일 입출력 (필요시)  

### 🟡 📝 코드 품질  
- 알고리즘 로직은 **따로 함수/클래스로 분리**  
- 주요 함수에는 **주석(docstring) 필수**  
- 한 줄 한 줄 **무슨 뜻인지 주석 달기**

## 🟢 9. 실행 예시로 전체 흐름 보기  

```
# 1. 시작하기
mini-git> init "홍길동"
Initialized repository.
Current branch: main
Current user: 홍길동

# 2. 첫 커밋
mini-git> commit "첫 화면 만들기"
[main a1b2c3] 첫 화면 만들기

# 3. 새 가지(브랜치) 만들기
mini-git> branch login-feature
Created branch: login-feature

# 4. 그 가지로 이동
mini-git> switch login-feature
Switched to branch: login-feature

# 5. 거기서 작업하고 커밋
mini-git> commit "로그인 버튼 추가"
[login-feature d4e5f6] 로그인 버튼 추가

mini-git> commit "로그인 로직 완성"
[login-feature g7h8i9] 로그인 로직 완성

# 6. 메인으로 돌아와서 다른 작업
mini-git> switch main
Switched to branch: main

mini-git> commit "회원가입 페이지 추가"
[main j1k2l3] 회원가입 페이지 추가

# 7. 전체 역사 보기 (부모가 먼저 나옴!)
mini-git> log
commit a1b2c3 (홍길동, 2024-01-15 09:00:00) [main]
첫 화면 만들기
commit j1k2l3 (홍길동, 2024-01-15 10:00:00) [main]
회원가입 페이지 추가
commit d4e5f6 (홍길동, 2024-01-15 11:00:00) [login-feature]
로그인 버튼 추가
commit g7h8i9 (홍길동, 2024-01-15 12:00:00) [login-feature]
로그인 로직 완성

# 8. 두 커밋 사이 최단 경로
mini-git> path a1b2c3 g7h8i9
Path: a1b2c3 -> d4e5f6 -> g7h8i9

# 9. 키워드로 검색
mini-git> search "로그인"
Found 2 commits:
- d4e5f6: 로그인 버튼 추가
- g7h8i9: 로그인 로직 완성

# 10. 작성자로 검색
mini-git> search --author="홍길동"
Found 4 commits:
...

# 11. 정렬해서 보기
mini-git> log --sort-by=author
...
```

## 🟢 12. 자주 묻는 질문 (FAQ)  

### 🟡 Q: 커밋 해시는 어떻게 만드나요?  
**A**: 자유입니다! 단, **중복 안 되게**만 만드세요.  
- 간단한 방법: `001`, `002`, `003`... (카운터)  
- 랜덤 방법: `random` 모듈로 6글자 랜덤 문자열  
- 시간 기반: `timestamp + random`  

### 🟡 Q: 위상 정렬 왜 해야 하나요?  
**A**: `LOG` 출력할 때 **"부모가 자식보다 먼저 나와야 한다"**는 규칙 때문입니다.  
Git도 `git log` 치면 옛날 커밋이 위에, 새 커밋이 아래에 나오잖아요? 그게 위상 정렬입니다.  

### 🟡 Q: 역색인(Inverted Index) 꼭 써야 하나요?  
**A**: 네, **필수**입니다. 전수 조사(O(N)) 하지 말고 색인 바구니 위치를 평균 O(1)에 찾으라는 뜻이야. 결과 K개를 꺼내는 비용 O(K)는 추가돼.  
커밋 1만 개면 전수 조사는 1만 번, 역색인은 1번 만에 찾습니다.  

### 🟡 Q: 정렬 알고리즘 직접 짜야 하나요?  
**A**: 네, **필수**입니다. `sorted()` 쓰면 안 돼요.  
이건 "정렬이 어떻게 돌아가는지 알기 위해" 일부러 막아둔 거예요.  

### 🟡 Q: 데이터 파일에 저장해야 하나요?  
**A**: **안 해도 됩니다.** 메모리에서만 돌아가면 돼요. (프로그램 끄면 다 날아가는 게 정상)  

### 🟡 Q: 브랜치 합치기(Merge)도 해야 하나요?  
**A**: **보너스**입니다. 본 과제에는 없고, 하고 싶으면 도전하세요!

## 🟢 14. 마무리: 이걸 왜 배우는 건가요?  

이 과제를 다 하고 나면 여러분은 **이런 걸 설명할 수 있게 됩니다**:  

1. **"Git 커밋이 왜 DAG(방향성 비순환 그래프)인가?"**  
   → 부모가 자식을 가리키고, 순환이 없으니까요!  

2. **"왜 `git log`에서 부모가 먼저 나오나?"**  
   → 위상 정렬로 정렬했으니까요!  

3. **"두 커밋 사이 최단 경로는 어떻게 찾나?"**  
   → BFS(너비 우선 탐색)로 찾아요!  

4. **"역색인이 왜 빠른가?"**  
   → 단어→문서 매핑을 미리 해놔서 전체를 안 뒤져도 되니까요!  

5. **"정렬 알고리즘의 시간복잡도와 안정 정렬이 뭔지 아나?"**  
   → 직접 짜봐서 압니다!  

이건 **알고리즘 공부의 기초**가 되고, **코딩 테스트**에서도 엄청나게 도움이 됩니다.
