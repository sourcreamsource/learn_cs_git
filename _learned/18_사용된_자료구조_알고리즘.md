# 🟩 사용 중인 자료구조와 알고리즘  

<br>

## 🟢 자료구조  

| 자료구조 | 용도 | 위치 |  
|---|---|---|
| 해시맵 `dict` | 커밋 해시로 커밋을 빠르게 조회 | `git-app/repositories/commit_repository.py:12` |  
| 해시맵 `dict` | 브랜치 이름과 최신 커밋 연결 | `git-app/repositories/branch_repository.py:10` |  
| 리스트 `list` | 커밋의 부모, 정렬 결과, 경로 저장 | `git-app/models/commit.py:28` |  
| 집합 `set` | 방문한 커밋과 발급한 해시의 중복 방지 | `git-app/graph/paths.py:63`, `git-app/utils/hash_generator.py:82` |  
| 큐 `deque` | BFS와 위상 정렬에서 먼저 들어온 항목부터 처리 | `git-app/graph/paths.py:46`, `git-app/graph/topological_sort.py:47` |  
| 스택 `list` | 퀵 정렬 작업을 나중에 넣은 것부터 처리 | `git-app/sort/quick_sort.py:32` |  
| 인접 리스트 | 커밋 그래프의 연결 관계 표현 | `git-app/graph/paths.py:12` |  
| 역색인 | 단어·작성자로 관련 커밋을 빠르게 검색 | `git-app/index/inverted_index.py:6` |  
| 2차원 DP 테이블 | 두 파일의 공통 줄과 차이 계산 | `git-app/bonus/diff.py:20` |  
| DAG | 커밋 역사를 순환 없는 방향 그래프로 표현 | `git-app/validators/dag_validator.py` |  

DAG는 **Directed Acyclic Graph**, 즉 **방향성 비순환 그래프**다.

## 🟢 알고리즘  

| 알고리즘 | 실제 용도 | 위치 |  
|---|---|---|
| BFS | 두 커밋 사이의 최단 경로 탐색 | `git-app/graph/paths.py:40` |  
| BFS | 특정 커밋의 모든 조상 탐색 | `git-app/graph/paths.py:60` |  
| Kahn 위상 정렬 | 부모 커밋이 자식보다 먼저 나오도록 정렬 | `git-app/graph/topological_sort.py:40` |  
| 사이클 탐지 | 커밋 그래프가 DAG인지 검사 | `git-app/validators/dag_validator.py:8` |  
| 병합 정렬 | 날짜·작성자·경로 이웃 정렬 | `git-app/sort/merge_sort.py:12` |  
| 퀵 정렬 | 병합 정렬과 성능 비교 실습 | `git-app/sort/quick_sort.py:12` |  
| 역색인 검색 | 전체 커밋을 훑지 않고 단어·작성자로 검색 | `git-app/index/inverted_index.py:50` |  
| LCS 동적 계획법 | 두 파일의 추가·삭제·공통 줄 계산 | `git-app/bonus/diff.py:7` |  
| SHA-1 해싱 | 커밋 식별자 후보 생성 | `git-app/utils/hash_generator.py:42` |  

LCS는 **Longest Common Subsequence**, 즉 **최장 공통 부분 수열**이다.  



<br><br>

## 🟢 핵심만 요약  

이 프로젝트에서 학습해야 할 중심 내용은 다음 7가지다.  

1. 해시맵  
2. DAG  
3. BFS  
4. Kahn 위상 정렬  
5. 역색인  
6. 병합 정렬과 퀵 정렬  
7. LCS 동적 계획법  

SHA-1은 사용하지만 암호나 비밀번호 보호용이 아니다. 이 프로젝트에서는 커밋 식별자 생성에만 사용한다.  

이번에는 코드 확인만 했으며 파일은 수정하지 않았다. `.env`, API Key, 토큰도 읽거나 출력하지 않았다.
