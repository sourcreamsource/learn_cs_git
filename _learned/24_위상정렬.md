## 🟢 1. 비유: 요리 순서 / 선수과목  

### 🟡 상황: 김치찌개 만들기  
```
1. 물 끓이기
2. 김치 썰기
3. 고기 썰기
4. 김치 볶기 (2번 후)
5. 고기 볶기 (3번 후)
6. 물 붓고 끓이기 (1, 4, 5번 후)
7. 양념 넣기 (6번 후)
8. 완성!
```

### 🟡 의존성 그래프 (화살표: "이게 먼저 해야 함")  
```
물끓이기 → 물붓기 ← 김치볶기 ← 김치썰기
              ↑
           고기볶기 ← 고기썰기
              ↓
           양념넣기 → 완성
```

### 🟡 위상 정렬 결과 (가능한 순서 중 하나)  
```
물끓이기 → 김치썰기 → 고기썰기 → 김치볶기 → 고기볶기 → 물붓기 → 양념넣기 → 완성
```

## 🟢 3. 두 가지 대표 알고리즘  

### 🟡 방법 1: 칸(Kahn) 알고리즘 - **진입 차수(Indegree) 이용** ⭐ 추천  
> **아이디어**: "아무도 가리키지 않는 노드(진입차수 0)부터 꺼내자"  

#### 단계별 과정  
```
그래프:     A → C ← B
            ↓
            D

1. 진입차수 계산: A:0, B:0, C:2, D:1
2. 큐에 진입차수 0인 것 넣기: [A, B]
3. A 꺼내서 출력 → C의 진입차수 1로 감소
4. B 꺼내서 출력 → C의 진입차수 0 됨 → 큐에 넣기
5. C 꺼내서 출력 → D의 진입차수 0 됨 → 큐에 넣기
6. D 꺼내서 출력
7. 결과: A, B, C, D (또는 B, A, C, D)
```

#### 파이썬 구현  
```python
from collections import deque

def topological_sort_kahn(graph):
    """
    graph: {노드: [자식노드들]} 형태의 인접 리스트
    예: {'A': ['C'], 'B': ['C'], 'C': ['D'], 'D': []}
    """
    # 1. 진입차수 계산
    indegree = {node: 0 for node in graph}
    for node in graph:
        for child in graph[node]:
            indegree[child] += 1
    
    # 2. 진입차수 0인 노드들 큐에 넣기
    queue = deque([node for node in graph if indegree[node] == 0])
    result = []
    
    # 3. 큐가 빌 때까지 반복
    while queue:
        node = queue.popleft()
        result.append(node)
        
        # 이 노드를 가리키는 자식들의 진입차수 줄이기
        for child in graph[node]:
            indegree[child] -= 1
            if indegree[child] == 0:
                queue.append(child)
    
    # 4. 순환 체크 (결과 개수가 노드 수랑 다르면 순환 있음)
    if len(result) != len(graph):
        raise ValueError("순환이 있습니다! DAG가 아닙니다.")
    
    return result
```

### 🟡 방법 2: DFS 기반 - **완료 순서 역순**  
> **아이디어**: 깊이 들어가서 **더 갈 곳 없으면(자식 다 처리되면) 결과에 추가**  

#### 파이썬 구현  
```python
def topological_sort_dfs(graph):
    visited = set()
    result = []
    
    def dfs(node):
        visited.add(node)
        for child in graph[node]:
            if child not in visited:
                dfs(child)
        # 모든 자식 처리 끝난 후 추가 (스택에 쌓임)
        result.append(node)
    
    for node in graph:
        if node not in visited:
            dfs(node)
    
    # 역순이 위상 정렬 순서
    return result[::-1]
```

## 🟢 4. Mini Git에 적용하기  

### 🟡 그래프 방향 주의!  
- **저장된 방향**: 자식 → 부모 (Git 방식)  
- **위상 정렬용 그래프**: 부모 → 자식 (시간 순서)  
- **변환 필요**: `parents` 리스트를 뒤집어서 `children` 그래프 만들기  

### 🟡 변환 코드  
```python
def build_children_graph(commits):
    """부모→자식 방향 그래프 만들기"""
    children = {hash_val: [] for hash_val in commits}
    
    for hash_val, commit in commits.items():
        for parent_hash in commit.parents:
            if parent_hash in children:
                children[parent_hash].append(hash_val)
    
    return children

# 사용 예
children_graph = build_children_graph(repo.commits)
# {'C0': ['C1'], 'C1': ['C2', 'C4'], 'C2': ['C3'], 'C4': ['C5'], 'C3': ['C5'], 'C5': []}

sorted_commits = topological_sort_kahn(children_graph)
# ['C0', 'C1', 'C2', 'C4', 'C3', 'C5']  ← 부모가 먼저 나옴!
```

## 🟢 5. 시간/공간 복잡도  

| 알고리즘 | 시간 | 공간 | 특징 |
|----------|------|------|------|
| **Kahn (BFS)** | O(V + E) | O(V) | 큐 사용, 진입차수 배열 필요, **순환 감지 쉬움** |
| **DFS** | O(V + E) | O(V) | 재귀/스택 사용, 완료순서 역순, 구현 간단 |

> **V = 노드 수(커밋 수), E = 간선 수(부모-자식 관계 수)**  
> 둘 다 **선형 시간**으로 매우 빠름!

## 🟢 6. 핵심 포인트 & 주의사항  

### 🟡 1. DAG만 가능!  
- 순환(Cycle) 있으면 **위상 정렬 불가능**  
- Git은 본질적으로 DAG라서 걱정 없지만, 안전장치로 체크하는 게 좋음  

### 🟡 2. 결과가 유일하지 않음  
```
A → C
B → C
```
- `A, B, C` 또는 `B, A, C` 둘 다 정답  
- **요구사항**: "사전순으로 가장 작은 것" 등 tie-break 규칙 있으면 추가 구현 필요  

### 🟡 3. Mini Git LOG 요구사항  
> "부모 커밋이 항상 자식 커밋보다 먼저 출력되도록"  
> → **위상 정렬 필수!**
