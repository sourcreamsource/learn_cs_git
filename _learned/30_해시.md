# 🟩 30_해시와 커밋 해시 (Hash & Commit Hash) - 쉽게 이해하기  

> **한 줄 요약**: **데이터를 고정된 길이의 "지문"으로 만드는 함수**  
> **Git에서**: 커밋 내용 전체를 해시로 만들어 **고유 ID**로 사용  

<br><br>

## 🟢 1. 비유: 사람 지문 / 주민등록번호  

| 현실 세계 | Git 세계 |
|-----------|----------|
| **사람** | **커밋 (데이터 뭉치)** |
| **지문** (고유, 안 변함) | **해시 값** (고유, 내용 바뀌면 바뀜) |
| **주민번호** (관리용 ID) | **커밋 해시** (조회용 키) |

- **같은 사람 = 같은 지문**  
- **같은 커밋 내용 = 같은 해시**  
- **내용 조금만 바뀌어도 → 완전히 다른 해시** (눈사태 효과)  

<br><br>

## 🟢 2. 해시 함수란?  

### 🟡 정의  
> **임의의 길이 입력 → 고정된 길이 출력**  
> 입력: "안녕하세요" (임의 길이)  
> 출력: "a1b2c3d4e5f6..." (항상 64자 등 고정)  

### 🟡 좋은 해시 함수의 조건  
| 조건 | 설명 |
|------|------|
| **결정적** | 같은 입력 → 항상 같은 출력 |
| **빠름** | 계산이 빨라야 함 |
| **일방향** | 해시 → 원본 복원 **불가능** |
| **충돌 저항** | 다른 입력 → 같은 출력 **매우 어려움** |
| **눈사태 효과** | 입력 1비트 변경 → 출력이 **완전히 달라짐** |

<br><br>

## 🟢 3. Git이 쓰는 SHA-1 (이제 SHA-256도 씀)  

### 🟡 SHA-1 예시  
```
입력: "commit 1234567890 HongGilDong <hong@email.com> 1705281600 +0900\n\n초기 커밋\n"
출력: "a1b2c3d4e5f6789012345678901234567890abcd"  (40자 16진수 = 160비트)
```

### 🟡 Git 커밋 해시 계산 대상  
```
커밋 객체 내용:
- 트리 해시 (파일 스냅샷)
- 부모 커밋 해시들
- 작성자 이름, 이메일, 시간
- 커미터 이름, 이메일, 시간
- 커밋 메시지
```
> **이 중 하나만 바뀌어도 해시가 완전히 바뀜!**

## 🟢 4. Mini Git에서 해시 만들기 (간단 버전)  

### 🟡 방법 1: 카운터 (가장 단순)  
```python
commit_counter = 0

def generate_hash():
    global commit_counter
    commit_counter += 1
    return f"{commit_counter:06d}"  # "000001", "000002", ...

# 장점: 구현 쉽음, 중복 절대 없음
# 단점: 의미 없음, 분산 환경에서 충돌 가능
```

### 🟡 방법 2: 타임스탬프 + 랜덤 (추천)  
```python
import time
import random
import hashlib

def generate_hash():
    # 현재 시간(마이크로초) + 랜덤값 조합
    data = f"{time.time()}:{random.random()}:{random.randint(0, 999999)}"
    # SHA-256으로 해시화 (앞 8~12자만 써도 충분)
    return hashlib.sha256(data.encode()).hexdigest()[:12]
# 예: "a1b2c3d4e5f6"
```

### 🟡 방법 3: 내용 기반 (진짜 Git처럼)  
```python
import hashlib
import json
from datetime import datetime

def generate_content_hash(message, author, parents, timestamp=None):
    if timestamp is None:
        timestamp = datetime.now().isoformat()
    
    # 커밋 객체 직렬화 (순서 고정 중요!)
    commit_data = {
        "message": message,
        "author": author,
        "parents": sorted(parents),  # 순서 정렬로 결정적 보장
        "timestamp": timestamp
    }
    
    # JSON으로 직렬화 (키 정렬)
    content = json.dumps(commit_data, sort_keys=True, separators=(',', ':'))
    
    # SHA-256 해시
    return hashlib.sha256(content.encode()).hexdigest()[:12]
```

## 🟢 5. 해시 충돌 (Collision) 이란?  

### 🟡 정의  
> **서로 다른 입력 → 같은 해시 출력**  

### 🟡 확률 (생일 역설)  
| 해시 길이 | 충돌 확률 50% 되는 입력 수 |
|-----------|---------------------------|
| 8자 (32비트) | 약 77,000개 |
| 12자 (48비트) | 약 2,000만 개 |
| 40자 (160비트, SHA-1) | 약 2^80 ≈ 10^24개 |

> **Mini Git 정도면 8~12자(16진수)면 충분!**  
> 그래도 **중복 체크 로직**은 넣는 게 안전  

### 🟡 중복 방지 코드  
```python
used_hashes = set()

def generate_unique_hash():
    while True:
        h = generate_hash()  # 위 방법 중 하나
        if h not in used_hashes:
            used_hashes.add(h)
            return h
```

## 🟢 6. 해시맵 (Dictionary) - 해시 테이블의 구현  

### 🟡 파이썬 `dict` = 해시맵  
```python
# 내부 동작 원리 (개념도)
hash_table = {
    # key의 해시값으로 버킷(저장소) 결정
    hash("a1b2c3") % 테이블크기: [("a1b2c3", 커밋객체)],
    hash("d4e5f6") % 테이블크기: [("d4e5f6", 커밋객체)],
    ...
}
```

### 🟡 시간복잡도  
| 연산 | 평균 | 최악 |
|------|------|------|
| **조회 (get)** | O(1) | O(n) |
| **삽입 (set)** | O(1) | O(n) |
| **삭제 (del)** | O(1) | O(n) |

> **평균 O(1)** = **상수 시간** = **개수 상관없이 빠름!**  
> 이게 `repository.commits[hash]`가 빠른 이유  

<br><br>

## 🟢 7. Mini Git 저장소 구조에 해시맵 적용  

```python
class Repository:
    def __init__(self):
        # 해시 → 커밋 객체 (해시맵으로 O(1) 조회)
        self.commits = {}  # {hash: Commit}
        
        # 브랜치명 → 커밋 해시
        self.branches = {}  # {branch_name: commit_hash}
        
        # HEAD: 현재 브랜치명
        self.head = None
        
        # 현재 사용자
        self.current_user = None
        
        # 역색인
        self.keyword_index = {}
        self.author_index = {}
    
    def get_commit(self, hash_val):
        """O(1) 조회"""
        return self.commits.get(hash_val)
    
    def add_commit(self, commit):
        """O(1) 삽입"""
        self.commits[commit.hash] = commit
    
    def has_commit(self, hash_val):
        """O(1) 존재 확인"""
        return hash_val in self.commits
```

## 🟢 8. 해시 관련 유용한 파이썬 도구  

### 🟡 `hashlib` - 표준 라이브러리  
```python
import hashlib

# SHA-256
hashlib.sha256(b"hello").hexdigest()
# '2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824'

# SHA-1 (Git 호환용)
hashlib.sha1(b"hello").hexdigest()
# 'aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d'

# 앞 8자만
hashlib.sha256(b"hello").hexdigest()[:8]
# '2cf24dba'
```

### 🟡 `hash()` 내장 함수 (주의!)  
```python
# 파이썬 실행마다 값이 다름 (보안상 랜덤화)
hash("hello")  # 실행할 때마다 달라짐!

# 영구 저장용으로는 쓰지 말 것!
# dict 키로는 괜찮음 (한 프로세스 내에선 일관됨)
```

## 🟢 9. 미니 실습: 해시 직접 만들어보기  

```python
import hashlib
import time
import random

def simple_hash(data):
    """간단 해시: SHA-256 앞 8자"""
    return hashlib.sha256(str(data).encode()).hexdigest()[:8]

# 1. 같은 입력 → 같은 출력
print("같은 입력:", simple_hash("hello"), simple_hash("hello"))

# 2. 조금만 바뀌어도 완전히 다름 (눈사태 효과)
print("hello:", simple_hash("hello"))
print("hell0:", simple_hash("hell0"))  # o → 0 하나만 바꿈

# 3. 커밋 해시 시뮬레이션
def make_commit_hash(msg, author, parent=""):
    content = f"{msg}|{author}|{parent}|{time.time()}"
    return simple_hash(content)

c1 = make_commit_hash("첫 커밋", "홍길동")
c2 = make_commit_hash("두 번째", "홍길동", c1)
c3 = make_commit_hash("세 번째", "김철수", c2)

print(f"C1: {c1}")
print(f"C2: {c2} (부모: {c1})")
print(f"C3: {c3} (부모: {c2})")

# 4. 해시맵 조회 속도 체험
import timeit

commits_dict = {f"hash{i}": f"data{i}" for i in range(100000)}

# 리스트에서 찾기 O(N)
lst = list(commits_dict.items())
t1 = timeit.timeit(lambda: [v for k, v in lst if k == "hash99999"], number=100)

# 딕셔너리에서 찾기 O(1)
t2 = timeit.timeit(lambda: commits_dict.get("hash99999"), number=100)

print(f"리스트 탐색: {t1:.4f}초")
print(f"딕셔너리 조회: {t2:.4f}초")
print(f"속도 차이: {t1/t2:.0f}배 빠름!")
```

### 🟡 실행 결과 예시  
```
같은 입력: a591a6d4 a591a6d4
hello: a591a6d4
hell0: 5d41402a  ← 완전히 다름!
C1: 3f2a1b4c
C2: 7e8d9f0a (부모: 3f2a1b4c)
C3: 1b2c3d4e (부모: 7e8d9f0a)
리스트 탐색: 2.3456초
딕셔너리 조회: 0.0001초
속도 차이: 23456배 빠름!
```

## 🟢 10. 핵심 포인트 정리  

### 🟡 커밋 해시 생성 시 체크리스트  
- [ ] **중복 안 되게** (세트나 카운터로 관리)  
- [ ] **결정적**이게 (같은 내용 → 같은 해시) - 내용 기반일 때  
- [ ] **충돌 확률 낮게** (최소 8자 이상, 12자 권장)  
- [ ] **빠르게** 생성되게  

### 🟡 해시맵 사용할 때  
- [ ] 키는 **불변 객체** (문자열, 숫자, 튜플)  
- [ ] `in` 연산자로 존재 확인: `if hash in repo.commits`  
- [ ] `.get()`으로 안전하게 조회: `repo.commits.get(hash)`
